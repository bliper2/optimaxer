Snapshot of the repository at v2.15.7. This describes implemented scope, not a parity promise. The Rust desktop app is the primary target for the UI work; the PowerShell and Linux editions remain independent products.

## Rust desktop baseline and gaps

The Rust app has eleven Optimaxer pages: Overview, Performance, Processes, Gaming, Activity, Tweaks, Services, Startup, Cleaner, Network and Tools. Overview samples CPU, physical memory, system-drive capacity, uptime and process count. Performance charts CPU, memory and aggregate receive/send byte rates from active non-loopback adapter counters once per second while Overview or Performance is visible. Virtual adapters can be included, so the readings are labeled adapter traffic rather than internet throughput. Unsupported counters are shown as unavailable. The read-only Processes page samples each accessible process's CPU time, working set and image path every three seconds while open; protected or inaccessible process fields remain unavailable. CPU is normalized to total logical processor capacity and is a short-interval estimate. The Gaming page displays current state for four existing reversible gaming tweaks and offers hardware-filtered apply/undo through the existing confirmation flow. Per-game executable profiles, GPU preferences, standalone Game Mode/DVR status and gaming history are not implemented. Publisher, GPU, temperature, disk activity, process termination and process inspection details are not implemented. The latest 100 confirmed tweak apply/undo batches are saved locally. Activity merges these records with up to 100 bounded output records for confirmed service, startup, cleaner, DNS, network reset, tool, installer launch, registry export and undo-all jobs in one timestamp-sorted, searchable timeline. Apply entries retain the exact change-preview lines; undo entries identify saved-original counts and verification without duplicating registry values. System-action records contain captured output only; they do not verify final state or provide undo data. Read-only scans and benchmarks are excluded. Separate `operations.json` preserves these logs in the app data directory.

Settings expose system/light/dark mode, Windows/Classic/Material control styling, 16 named color palettes, saved custom accent, reduced motion, comfortable/compact density, 90–125% interface scale, update checks, download location and restore-point preference. Palette choice remains separate from control shape; custom accent text and action fills are contrast-adjusted. Versioned appearance presets can be imported/exported and version 1 presets migrate with default density and scale. Adjustable corner-radius controls and full custom surface editing are not implemented. The Optimaxer rail can collapse to icons and remembers that choice; Store navigation stays expanded. The Tweaks page supports named selection profiles, portable JSON import/export and a read-only differences view for two saved profiles. Tweak batches that change settings requiring a Windows restart set a persisted reminder, cleared after system uptime resets. Performance does not yet include GPU, disk-activity or temperature readings. Gaming executable profiles, notification center and system snapshot browser are not implemented. Existing exact-undo records, service backups and confirmation previews remain the source of truth for their respective operations.

This audit phase adds a Gaming page for existing reversible catalog settings and adds it to the searchable command palette. `Ctrl+K` and the visible Commands button also expose Store search, Downloads and Settings. The palette routes only to existing operations and does not trigger system changes.

## Next implementation constraints

- Keep controls attached only to implemented operations. New destinations require a complete read/change/restore path before they appear in navigation.
- Add measurements only when a real platform probe, error state and units are defined.
- Extend theme choices through validated token sets and contrast checks; keep shape style and color palette separate.
- Keep PowerShell-only Windows operations out of Linux and Rust until each port has a tested native implementation.
- Update this comparison when source behavior changes; use the edition READMEs for operational instructions and [verification.md](verification.md) for test evidence and remaining machine-level checks.
