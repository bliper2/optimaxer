## Rust desktop baseline and gaps

The Rust app has fourteen Optimaxer pages: Overview, Smart Optimize, Performance, Diagnostics, System Snapshot, Processes, Gaming, Activity, Tweaks, Services, Startup, Cleaner, Network and Tools. Smart Optimize reads hardware traits and current tweak status, explains the automatic plan and exclusions, and passes selected IDs to the existing Tweaks preview and confirmation flow. It does not apply settings itself. Overview samples CPU, physical memory, system-drive capacity, uptime and process count. Performance charts CPU, memory, aggregate physical-disk throughput, receive/send byte rates from active non-loopback adapters, busiest GPU-engine utilization and dedicated GPU memory on a background worker while Overview or Performance is visible with a user-configurable 1, 2 or 5 second interval and 30, 60 or 120 second chart window. It captures a selected Windows process for 30 seconds with PresentMon, verifies the download against GitHub's published SHA-256, and records average FPS, 1% and 0.1% lows, p99 frame time, frame count and stutters. Each capture also samples Windows DPC/interrupt counters for five seconds when available, queries current timer resolution, attempts ten TCP connections to 1.1.1.1 port 53, and reads the latest Diagnostics-Performance boot event. TCP averages, jitter and failures measure that DNS endpoint, not ICMP ping or game-server latency. Boot duration is comparable only across distinct boot-event timestamps. Before/after comparisons require matching process names and are explicitly observational. Captures are capped at 40; executable and history live under the app data directory. Disk readings use the Windows PhysicalDisk `Disk Bytes/sec` counter; virtual network adapters may be included, so network readings are adapter traffic rather than internet throughput. Unsupported counters are shown as unavailable. Diagnostics runs only the read-only SFC `/verifyonly` and DISM `/Online /Cleanup-Image /ScanHealth` checks, displaying exit codes and bounded captured output; repair actions remain in Tools. System Snapshot stores the current OS, CPU, GPU names, logical thread count, memory, system-volume capacity and uptime locally, retaining the 30 newest records; it compares the two newest captures for changes to inventory and total capacity, excluding changing used-space and uptime readings. It is an inventory and cannot restore Windows. The read-only Processes page samples each accessible process's CPU time, working set and image path every three seconds while open; protected or inaccessible process fields remain unavailable. CPU is normalized to total logical processor capacity and is a short-interval estimate. The Gaming page displays current state for four existing reversible gaming tweaks and offers hardware-filtered apply/undo through the existing confirmation flow. It supports manually added executable profiles for Windows per-game GPU preference, with exact saved-original restoration and external-change conflict protection. Preference-only JSON presets can be imported/exported; executable paths and saved Windows values are excluded. The read-only library scan lists installed games from bounded Steam app manifests and Epic launcher `.item` manifests; it does not traverse game folders or change launcher data. Users select an executable in the detected install folder before saving a game profile. Steam library manifests that cannot be read are skipped; Epic invalid manifests are reported. Per-profile history displays the latest matching apply and restore records from the bounded operation log. The Gaming page reports whether Game Mode, per-user Game DVR capture, machine Game DVR policy and the global fullscreen-optimization override match the registry settings used by Optimaxer tweaks. This is configuration status, not live Game Bar or capture activity. The four non-opt-in Safe gaming tweaks offer per-row apply and undo review through the shared confirmation flow. Machine-wide DVR policy and the global fullscreen override remain opt-in in Tweaks. The Performance page provides user-triggered PresentMon captures and observational comparisons. Process inspection reveals the selected executable path and embedded CompanyName metadata when available; this is descriptive file metadata, not a verified publisher identity. Process termination is not implemented. The latest 100 confirmed tweak apply/undo batches are saved locally. Activity merges these records with up to 100 bounded system-action records for confirmed service, startup, cleaner, DNS, network reset, tool, installer launch, registry export and undo-all jobs in one timestamp-sorted, searchable timeline. Operation records label worker-reported warnings and errors and retain bounded output; a finished worker does not verify final system state or provide undo data. The download manager can cancel downloads, and Cleaner size scans can be cancelled without retaining partial results. Path previews, other read-only scans, benchmarks and running Windows system-changing jobs cannot currently be cancelled. Separate `operations.json` preserves these records in the app data directory.

Overview recommends eligible inactive Smart Optimize settings, offers a cleanup scan when measured system-drive use reaches 90%, and links to startup review, diagnostics, update checks, restore-point creation and memory cleanup. System changes continue through their existing confirmation flows; Overview itself never applies tweaks or deletes files.

Smart Optimize is a dedicated, read-only planning page. It reports detected form factor, storage, RAM, processor threads and graphics adapters; lists inactive automatic recommendations; summarizes hardware rules and excluded tweaks; and refreshes current tweak state on demand. The review action selects only the computed plan in Tweaks. Changes remain subject to the existing preview, confirmation, restore-point option, saved-original backup and verification flow.

Settings expose system/light/dark mode, Windows/Classic/Material control styling, 16 named color palettes, custom accent and editable light/dark surfaces, reduced motion, comfortable/compact density, 90–125% interface scale, optional 0–16 px corner radius, update checks, download location and restore-point preference. Palette choice remains separate from control shape; custom text and accent are adjusted for contrast. Version 4 appearance presets include custom surfaces; versions 1 through 3 import with defaults for fields they predate. Failed settings writes are reported; appearance and restore-point changes revert in the live UI, while other preferences remain active for the session and show that they were not saved. The Optimaxer rail can collapse to icons and remembers that choice; Store navigation stays expanded. The Tweaks page supports named selection profiles, portable JSON import/export and a read-only differences view for two saved profiles. Tweak batches that change settings requiring a Windows restart set a persisted reminder, cleared after system uptime resets. The notification center aggregates restart, update, operation and download status, with relevant actions and bounded dismissal storage. Performance does not include GPU temperature or dedicated-memory capacity readings. Gaming profiles require a user-selected executable. Each profile shows matching records from the latest 100 bounded system operations. The Performance page provides user-triggered PresentMon captures and observational comparisons. Existing exact-undo records, service backups and confirmation previews remain the source of truth for their respective operations.

The Tweaks catalog supports applied-state, recommendation, favorite and hardware-compatibility filters, plus name, risk and status sorting within categories. Favorite IDs persist with local settings. These controls only change catalog visibility and ordering. A pinned action bar stays visible while the catalog scrolls and offers preview, undo, save-profile and clear-selection actions with recommended and review counts. The command palette is fuzzy-searchable, labels results by category, and routes to pages, Store search, downloads, settings, tweak filtering and the existing 17 color palettes. It lists up to eight newest saved Activity records and opens each through the existing timestamp search. An unmatched query offers a direct tweak search. Palette changes use the same checked settings save and rollback behavior as Settings. Arrow keys select results and Enter runs the selected navigation or preference action; the palette does not trigger system changes.

## Next implementation constraints

- Keep controls attached only to implemented operations. New destinations require a complete read/change/restore path before they appear in navigation.
- Add measurements only when a real platform probe, error state and units are defined.
- Extend theme choices through validated token sets and contrast checks; keep shape style and color palette separate.
- Keep PowerShell-only Windows operations out of Linux and Rust until each port has a tested native implementation.
- Update this comparison when source behavior changes; use the edition READMEs for operational instructions and [verification.md](verification.md) for test evidence and remaining machine-level checks.
